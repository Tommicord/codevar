# Plan: kuitui-assets crate — build.rs-generated compressed/vectorized asset bindings

## Scope

Create a new workspace crate `codevar-kuitui-assets` (`crates/kuitui-assets/`) that generates highly compressed Rust bindings for assets inside `assets/` at build time via `build.rs`. The crate supports:

- **Vectorization** (raster → vector SVG) for icons, logos, and flat artwork using a native Rust vectorizer.
- **Binary compression** (zstd) for photos and other non-vectorizable resources.
- **Passthrough** (no transform) for fonts and already-compact binary assets.
- Zero-cost runtime access: static `&'static [u8]` bindings generated by `build.rs`, decompressed lazily on first access.

The crate is a leaf crate (no other crate depends on it yet). It depends only on `codevar-base`, `codevar-logger`, and workspace crates.

## Design decisions

### 1. Vectorization library: VTracer

**Decision:** Use `vtracer` (visioncortex/vtracer, Rust 1.0 alpha) as the vectorization engine, invoked from `build.rs` as a build-dependency.

**Why:** VTracer is the most efficient native Rust vectorizer found:
- Linear pipeline (no expensive optimal-polygon search like Potrace), fast on large images.
- Handles color images natively (unlike Potrace, which is B&W only).
- Compact output: stacking strategy avoids shapes with holes; curve simplification often halves file size vs Adobe Illustrator Image Trace.
- Pure Rust library API (`Config::build()?.to_svg(&img)`), no external toolchain required at build time.
- Presets (`Poster`, `Photo`, `Icon`) map well to UI asset categories.
- Benchmark data: median SVG 37.2 KB vs ImageTracer 132.5 KB / AutoTrace 278.2 KB; lowest anchor-point count among classical tracers.

**Fallback:** If `vtracer` is unavailable at build time (missing dependency or build failure), emit the raw PNG bytes unchanged with a `cargo:warning`. The build must not fail.

**Not chosen:** `img2svg` (strong alternative, ~60–70 ms for 512×512, but VTracer's compactness and stacking strategy are better for memory-constrained UI assets). `covecto` (dual-engine, also strong, but less benchmark data). `potrace` (B&W only, needs mkbitmap pre-processing for color).

### 2. Compression library: zstd

**Decision:** Compress non-vectorizable binary assets (photos, already-vector SVGs, fonts) with **zstd** at build time in `build.rs`, storing compressed `.bin.zst` blobs in `OUT_DIR`.

**Why:** zstd offers the best speed/compression tradeoff for embedded assets. Decompression at runtime is fast (~single digit µs per KB). Alternatives considered: brotli (better ratio, slower decode), lz4 (faster decode, worse ratio), deflate (ubiquitous but worse ratio). zstd is the workspace-consistent choice given `image = 0.25.10` is already a workspace dependency (for decoding PNG/JPEG before vectorization).

### 3. Asset classification pipeline (build.rs)

Each file under `assets/` is classified by extension and content:

| Category | Extensions | Transform | Output |
|---|---|---|---|
| Vectorizable raster | `.png`, `.jpg`, `.jpeg`, `.webp`, `.bmp`, `.tga` | VTracer → SVG → zstd compress | `OUT_DIR/<name>.svg.zst` + static |
| Photo / non-vectorizable | `.png`, `.jpg`, `.jpeg`, `.webp` (complex) | zstd compress raw | `OUT_DIR/<name>.bin.zst` + static |
| Already vector | `.svg` | zstd compress | `OUT_DIR/<name>.svg.zst` + static |
| Fonts | `.ttf`, `.otf`, `.woff`, `.woff2` | passthrough (already compact) | `OUT_DIR/<name>` + static `include_bytes!` |
| Other binary | anything else | passthrough | `OUT_DIR/<name>` + static `include_bytes!` |

**Vectorization quality tiers** (per-directory or per-file opt-in via a sidecar `assets/kuitui-assets.toml`):
- `icon` → `Preset::Poster`, `max_colors: Some(16)`, `mode: Polygon`
- `logo` → `Preset::Logo`, `max_colors: Some(32)`
- `photo` → skip vectorization, zstd only
- `default` → `Preset::Icon`, `max_colors: Some(8)`

### 4. Generated bindings structure

`build.rs` writes `OUT_DIR/assets.rs` included by `src/lib.rs` via `include!(concat!(env!("OUT_DIR"), "/assets.rs"))`.

Generated module structure mirrors `assets/` directory tree:

```
assets/
├── icons/
│   ├── save.png        →  assets::icons::SAVE_SVG (compressed SVG bytes)
│   └── delete.png      →  assets::icons::DELETE_SVG
├── photos/
│   └── bg.jpg          →  assets::photos::BG_BIN (compressed raw bytes)
└── fonts/
    └── regular.ttf     →  assets::fonts::REGULAR_TTF (raw bytes)
```

Each asset contributes:
- `pub static <NAME>_DATA: &[u8]` — compressed or raw bytes.
- `pub static <NAME>_META: AssetMeta` — `{ kind: AssetKind, original_size: usize, stored_size: usize, mime: Option<&'static str> }`.

Plus a registry:
- `pub static ASSETS: &[AssetEntry] = &[...]` — every asset with name, data, meta.

`AssetMeta` and `AssetEntry` are defined in `src/lib.rs`; `build.rs` only emits data statics and the registry.

### 5. Runtime API (src/lib.rs)

```rust
pub enum AssetKind { VectorSvg, Binary, Font, Raw }
pub struct AssetMeta { kind: AssetKind, original_size: usize, stored_size: usize, mime: Option<&'static str> }
pub struct AssetEntry { name: &'static str, data: &'static [u8], meta: AssetMeta }

pub struct Assets;
impl Assets {
    pub fn get(name: &str) -> Option<&'static AssetEntry>;
    pub fn iter() -> impl Iterator<Item = &'static AssetEntry>;
    pub fn decompress(data: &[u8]) -> Cow<'static, [u8]>;  // zstd decompress if needed
}
```

Decompression is lazy: `get(name)` returns the compressed/static bytes; callers decompress on demand via `decompress()` or a convenience `into_vec()`. This avoids decompressing all assets at startup (memory first).

### 6. Build script behavior (following kuitui/build.rs conventions)

- `OUT_DIR` and `CARGO_MANIFEST_DIR` are required env vars.
- Asset dir default: `<manifest_dir>/assets`; override via `CV_ASSETS_DIR`.
- `cargo:rerun-if-changed=` for the asset dir and each file.
- Missing/empty asset dir → empty module, not an error (matches kuitui shader behavior).
- VTracer unavailable → emit raw bytes + `cargo:warning`, build continues.
- Duplicate asset names (after sanitization) → build failure.
- All human messages via `cargo:warning`; `println!` only for `cargo:` directives.

### 7. Ident sanitization

Reuse the `sanitize_ident` pattern from `kuitui/build.rs` and `oclc/build.rs`: ASCII alphanumerics + `_`, everything else → `_`, leading digit gets `_` prefix. Directory names become module path segments. Non-injective mapping → duplicate detection is required.

### 8. no_std compatibility

Crate is `#![cfg_attr(not(test), no_std)]` + `extern crate alloc`, matching `truetype-core` and `truetype-gzip`. `build.rs` itself is `std` (build scripts always run with std). The generated bindings and runtime API use `alloc::vec::Vec`, `alloc::borrow::Cow`, `alloc::string::String`, `core::str::from_utf8`.

### 9. Error handling

No `.unwrap()` / `.expect()` / `panic!` in production code (per AGENTS.md). All fallible operations return `Result` or use `?`. Build script maps errors to `BuildFailure` enum with `Display` impl, matching `kuitui/build.rs` and `oclc/build.rs` patterns. `.unwrap()` allowed only in unit tests.

### 13. Open questions / risks

- **vtracer MSRV**: vtracer 1.0 alpha may require a newer Rust than 1.93.0. Need to verify compatibility or pin a compatible version. If incompatible, fall back to `img2svg` (edition 2024, Rust-native) or implement a minimal region-flood-fill vectorizer inline.
- **WASM target**: `vtracer` may not compile to wasm32-unknown-unknown. Need a `#[cfg(target_arch = "wasm32")]` fallback that skips vectorization and stores raw bytes. The crate targets WASM per project overview.
- **Build-time cost**: Vectorizing every icon at build time can be slow. Mitigation: only vectorize when `PROFILE=release` or when a `CV_VECTORIZE=1` env is set; in debug, store raw PNG.
- **Asset dir location**: The workspace root `assets/` only has `tf/` (fonts). The crate should point at `<manifest_dir>/../../assets` or be configured per consuming crate. Default to `<manifest_dir>/assets` and document the override.
